# dsh-telegram

[English](README.md) | Русский

Telegram внутри [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness): кнопка-«самолётик» в правом верхнем углу Web-интерфейса открывает полноценный оверлей Telegram — официальный MTProto через [GramJS](https://github.com/gram-js/gramjs), вход по QR в первую очередь, список диалогов, лента сообщений, композер и профили. Выделение объекта или рамка области внутри оверлея открывает окно комментария, которое отправляет ваш промпт в **активную сессию DSH** вместе с выделенными объектами.

Тот же плагин даёт агенту один инструмент `telegram`: чтение диалогов и истории, поиск, отправка текста и отметка прочтения.

- Оверлей доступен из любого раздела интерфейса (Conversation, «Плагины», страницы настроек), потому что живёт в слоте кадра `shell.overlay`.
- Никаких правок ядра: плагин — это одна строка бандла и его собственные файлы.
- Сессия Telegram не покидает узел: это credential-запись DSH, а не конфигурация и не `localStorage`.

## Требования

| Требование | Подробности |
|---|---|
| DeepSeek Harness | `>=0.2.2-rc.3` (проверяется через `engines.dsh`); разработка и проверка — на `0.2.2-rc.5` |
| Node | `>=24` |
| Учётные данные Telegram API | `api_id` и `api_hash` с <https://my.telegram.org/apps>, выданные для аккаунта, который нужно подключить |
| Сеть | Доступность дата-центров Telegram по MTProto — напрямую или через SOCKS5/MTProxy-прокси (см. [Прокси](#прокси)) |

## Установка

Плагин — это DSH-**бандл**: его `package.json` объявляет `dsh.bundle.patch`, а патч вставляет единственную строку `telegram`.

### С GitHub

pnpm 11 не запускает install-скрипты зависимостей без явного решения, а GramJS приносит три транзитивных пакета с такими скриптами (`bufferutil`, `utf-8-validate`, `es5-ext`). Ни одна из этих сборок не нужна. Объявите это один раз в `pnpm-workspace.yaml` профиля (`~/.dsh/profiles/web/pnpm-workspace.yaml`):

```yaml
allowBuilds:
  bufferutil: false
  utf-8-validate: false
  es5-ext: false
```

Затем установите:

```sh
dsh plugin --profile web add github:dadgrand/dsh-telegram
```

pnpm ставит пакет и две его runtime-зависимости (`telegram@2.26.22`, `qrcode-generator@2.0.4`) в профиль, а `dsh` добавляет `dsh-telegram` в `dsh.profile.bundles`.

Без этого блока первая команда `add` останавливается с `ERR_PNPM_IGNORED_BUILDS`: пакет уже попал в `package.json` профиля, но строка бандла ещё не зарегистрирована. Добавьте блок и повторите ту же команду `add` — она завершится и добавит строку. Как вариант, установите из локального каталога (ниже): там pnpm вообще не спрашивает про сборки.

### Из локального каталога

```sh
dsh plugin --profile web add /абсолютный/путь/к/dsh-telegram
```

Связанный каталог (link) держит собственный `node_modules`, а pnpm не устанавливает зависимости цели ссылки, поэтому сначала поставьте их внутри каталога:

```sh
cd /абсолютный/путь/к/dsh-telegram
npm install --omit=dev --ignore-scripts --no-audit --no-fund --no-package-lock
```

`--ignore-scripts` — намеренно: GramJS перечисляет необязательные нативные зависимости (`bufferutil`, `utf-8-validate`), чьи скрипты сборки не нужны и должны запускаться только с вашего явного согласия.

### Из интерфейса

«Настройки» → «Плагины» → «Добавить плагин» → **Локальный каталог** и выберите каталог плагина. Это та же установка связыванием.

### Перезапуск и проверка

```sh
dsh --profile web --dump-config | grep -A3 "== dsh-telegram"
dsh --profile web
```

После перезапуска кнопка-«самолётик» появляется в правом верхнем углу окна, поверх всех панелей. Удаление бандла (`dsh plugin --profile web remove dsh-telegram`) и перезапуск снимают строку, её маршруты и инструмент.

## Настройка

Правьте **свой** патч-слой — `~/.dsh/profiles/<профиль>/cordis.patch.yml`. Плагин никогда не переписывает свою конфигурацию, а пользовательский слой важнее патча бандла, поэтому ваши значения переживают обновления плагина.

```yaml
- id: telegram
  config:
    apiId: 1234567
    apiHashRef: TELEGRAM_API_HASH
    proxyMode: socks5
    proxyHost: 127.0.0.1
    proxyPort: 1081
```

У каждого поля есть значение по умолчанию, поэтому строка без `config` всё равно монтируется и сообщает `not_configured`.

| Поле | Тип | По умолчанию | Назначение |
|---|---|---:|---|
| `apiId` | целое `0…2147483647` | `0` | api_id с my.telegram.org; `0` = «не настроено» |
| `apiHash` | строка | `''` | api_hash (секрет); пусто = «не настроено» |
| `apiHashRef` | строка | `''` | Имя сохранённого секрета с хешем; **важнее `apiHash`** |
| `defaultPhone` | строка | `''` | Номер, который узел подставляет, если форма fallback отправлена пустой; никогда не возвращается в `/status` и не попадает на страницу |
| `connectionTimeoutMs` | целое | `20000` | Потолок одной попытки подключения |
| `dialogLimit` / `messageLimit` / `searchLimit` | целое | `30` / `25` / `10` | Потолки на один запрос |
| `textMaxLength` | целое | `4096` | Потолок исходящего текста |
| `bodyMaxBytes` | целое | `65536` | Потолок тела POST |
| `authTimeoutMs` | целое | `180000` | Время жизни попытки входа; продлевается каждым новым QR-токеном |
| `proxyMode` | `direct` \| `socks5` \| `mtproxy` | `direct` | Режим прокси; режим, отличный от `direct`, важнее `DSH_TELEGRAM_PROXY` |
| `proxyHost` / `proxyPort` | строка / целое | `127.0.0.1` / `1080` | Адрес прокси |
| `proxyUser` | строка | `''` | Имя пользователя SOCKS5 (не логируется) |
| `proxyPasswordRef` / `proxySecretRef` | строка | `''` | Имена секретов для пароля SOCKS5 / секрета MTProxy |
| `proxyTimeoutSec` / `proxyPreflightMs` | целое | `8` / `1500` | Таймаут рукопожатия, бюджет TCP-предпроверки |
| `selectionMaxObjects` | целое | `12` | Заявленный лимит промпта (читается из `/status`; см. раздел о промпте — промпт ограничивается в браузере, а не на узле) |
| `selectionTextPerObject` | целое | `500` | Заявленный лимит текста на объект (на узле не применяется) |
| `promptMaxChars` | целое | `6000` | Заявленный бюджет промпта (на узле не применяется) |
| `noteMaxChars` | целое | `2000` | Заявленный бюджет комментария (на узле не применяется) |
| `sendMode` | `queue` \| `steer` | `queue` | Режим доставки промпта по умолчанию |

`apiHash` — секрет. Предпочтите `apiHashRef`: DSH разрешает имя через своё хранилище секретов (сохранённый ключ или переменную окружения профиля `TELEGRAM_API_HASH`), и значение никогда не попадает в конфигурацию. Учтите: схема этого плагина валидируется, но формы в «Настройках» у неё нет — конфигурация правится только в патч-слое (или переменной окружения прокси, см. ниже).

## Вход

Откройте оверлей: экран входа показывает QR-код.

1. **QR (основной путь).** Telegram на телефоне → «Настройки» → «Устройства» → «Подключить устройство», затем отсканируйте. Код обновляется примерно каждые 30 секунд; `Обновить код сейчас` запрашивает новый сразу. Окно показывает обратный отсчёт до истечения.
2. **Fallback по номеру.** `Войти по номеру телефона` показывает цепочку номер → код → пароль двухшаговой проверки (2FA, с подсказкой от Telegram). `defaultPhone`, если задан, используется **узлом**: если отправить форму пустой, поле остаётся пустым, а номер не попадает в браузер. Оверлей знает только, задан ли такой номер (`/status` отдаёт `phoneConfigured`).
3. Попытка живёт 3 минуты (`authTimeoutMs`); каждый новый QR-токен её продлевает. По истечении вы возвращаетесь в `idle`.

Сессия входа (GramJS `StringSession`) хранится как credential-запись DSH `dsh-telegram/session` в `$DSH_HOME/.credentials.yaml` — не в конфигурации плагина, не в `localStorage` и не в логах. Оверлей и `/status` показывают только маску номера (`+7 9** ** **12`). `Выйти` удаляет локальную запись и уничтожает клиент; отзыв сессии на стороне Telegram выполняется с телефона.

Вход, выход и подтверждение QR доступны только человеку: у инструмента агента нет действий, которые могли бы их выполнить.

## Прокси

Многие сети блокируют прямой MTProto. Запустите локальный SOCKS5-прокси (плагин разрабатывался с локальным «сторожем» на `127.0.0.1:1081`) и укажите его плагину — либо в конфигурации:

```yaml
- id: telegram
  config:
    proxyMode: socks5
    proxyHost: 127.0.0.1
    proxyPort: 1081
```

либо через окружение, которое читается при активации плагина:

```sh
DSH_TELEGRAM_PROXY=socks5://127.0.0.1:1081
DSH_TELEGRAM_PROXY=socks5://user:pass@127.0.0.1:1081
DSH_TELEGRAM_PROXY=mtproxy://host:443?secret=<secret>
```

Приоритет: режим `proxyMode`, отличный от `direct`; иначе `DSH_TELEGRAM_PROXY`; иначе прямое подключение. Учётные данные из URL не логируются, а `/status` сообщает только режим, хост и порт.

Собственная поддержка `HTTP_PROXY` / `HTTPS_PROXY` в DSH не принимает URL `socks5://`, поэтому эти переменные плагину не помогают — прокси задаётся здесь.

Перед подключением узел проверяет TCP-эндпоинт прокси (1,5 с). Мёртвый или недоступный прокси даёт состояние `connection_failed` с диагностикой без секретов (`proxy_unreachable`, `connect_timeout`, `connect_refused`, `dc_unreachable`, `auth_key_unregistered`) вместо зависшего запроса. Учтите: GramJS принимает прокси только в конструкторе клиента, поэтому смена настроек применяется при пересоздании клиента (перезапуск плагина или `Повторить` в оверлее после ошибки).

## Выделение объекта или области и отправка агенту

Выделение — явный режим, поэтому обычный просмотр никогда не перехватывается.

1. Откройте оверлей и нажмите **Выделить** на панели оверлея. Строка-подсказка объясняет режим.
2. **Клик** по строке диалога, сообщению, медиа-чипу или карточке профиля → объект становится чипом в полосе выделения. Повторный клик убирает его. Повторное нажатие `Выделить` выходит из режима.
3. **Рамка области**: протяните прямоугольник по панели. Каждый выделяемый объект, чья площадь пересекается с рамкой не менее чем на 30 % меньшей фигуры, попадает в выделение — в порядке чтения.
4. Нажмите **Комментарий** (или `Комментарий` на панели), чтобы открыть окно комментария.
5. Напишите, что должен сделать агент, просмотрите предпросмотр промпта, при работающей целевой сессии выберите `В очередь` или `Прервать и вставить`, затем нажмите **Отправить**.

Куда уходит промпт: в **активную сессию DSH** — ту, которую Conversation открывал последней (она определяется по удержанию main-view). Окно всегда называет адресата; если активной сессии нет, оно предлагает `Открыть в новой сессии` (создаёт сессию в текущем рабочем пространстве и кладёт промпт в композер) и `Копировать`.

Промпт собирается детерминированно: сначала короткий человекочитаемый дайджест (`Telegram: N objects selected …`), затем ваш комментарий, затем огороженный блок JSON (`"schema": "dsh-telegram/selection@1"`) с выделенными объектами. Содержимое Telegram считается недоверенными данными: блок огорожен четырьмя обратными кавычками, и промпт явно сообщает, что это данные, а не инструкции. Сериализуются только поля из белого списка — номера телефонов, учётные данные API, строка сессии и QR-токены в промпт попасть не могут.

Ваш комментарий вставляется **экранированным, а не дословно**: управляющие символы и bidi-метки удаляются, табуляции заменяются пробелами, HTML и Markdown нейтрализуются, чтобы вставленный фрагмент не мог перестроить промпт. Бюджет применяется в браузере, а не на узле: до 50 выделенных объектов (полоса чипов помечает отброшенное), 500 символов текста на объект, 6000 символов на готовый промпт, 2000 на комментарий, причём каждое усечение помечается. Значения `selection*` / `promptMaxChars` / `noteMaxChars` в конфигурации — это значения по умолчанию, которые оверлей читает из `/status`; узел получает готовый текст и повторно его не ограничивает.

## Инструмент агента `telegram`

Один инструмент, один параметр `action`. Действия только на чтение безопасны для параллельных вызовов; `send_message` и `mark_read` — нет.

| Действие | Параметры | Результат |
|---|---|---|
| `status` | — | состояние настройки/движка/входа, маска номера, id пользователя, DC, время сохранения сессии, последняя ошибка |
| `whoami` | — | id пользователя, маска номера, имя, username, DC |
| `list_chats` | `limit` (1–30) | диалоги: id, тип (`user`/`chat`/`channel`), название, закреплён/архив, непрочитанные, последнее сообщение, время |
| `get_chat` | `chat_id` | один диалог |
| `get_messages` | `chat_id`, `limit` (1–100), `before` | сообщения с текстом, автором, `fromMe`, ответом, отметкой правки, метаданными медиа; плюс признак «есть более старые» |
| `send_message` | `chat_id`, `text` | отправленное сообщение |
| `mark_read` | `chat_id`, `up_to` | подтверждение прочтения |
| `search` | `query`, `chat_id` (необязательно), `limit` (1–50) | найденные сообщения |

```json
{ "action": "get_messages", "chat_id": "-1001234567890", "limit": 25, "before": 4200 }
```

Ответы — `{ "ok": true, "action": … , "result": … }` либо `{ "ok": false, "action": …, "error": { "code": …, "message": … } }`. `chat_id` берётся из `list_chats` (у каналов префикс `-100`). Инструмент не умеет входить и выходить, удалять, править, пересылать, закреплять, рассылать и вызывать «сырые» методы `Api.*`; бюджет вызова — 30 секунд.

## Диагностика

| Что видно | Что делать |
|---|---|
| `not_configured` / «Telegram не настроен» | задайте `apiId` и `apiHash` (или `apiHashRef`) в строке патча `telegram` |
| `engine_unavailable` | пакет `telegram` отсутствует в каталоге плагина; переустановите зависимости |
| `connection_failed` + `proxy_unreachable` | прокси не слушает заданный хост/порт; запустите его или исправьте конфигурацию |
| `connection_failed` + `connect_timeout` / `dc_unreachable` | прокси доступен, а Telegram — нет; проверьте его upstream |
| `auth_key_unregistered` | `apiId`/`apiHash` неверны или отозваны |
| `not_authenticated` | войдите из оверлея |
| `auth_expired` | попытка истекла; запросите новый код или обновите QR |
| `flood_wait` | подождите интервал, который просит Telegram |

`GET /api/dsh-telegram/status` отдаёт те же факты в JSON, включая `diagnostics`. Все маршруты доступны только с loopback, защищены проверкой источника и намеренно не требуют аутентификации для локального использования; это внутренний канал оверлея, а не публичный API.

## Что в пакете

## Известные ограничения

- **Модальные окна DSH перекрывают кнопку.** Оверлей живёт в кадре (`shell.overlay`, z-index 20), а модальные окна DSH рендерятся в `document.body` с z-index 1000/1100. Пока открыто приветственное окно, Preview Notice или «Настройки», они перехватывают клики по «самолётику» — закройте окно (`Continue`, `Понятно`, `×`), затем нажмите кнопку или `Alt+Shift+T`. Поднять плагин выше модальных окон нельзя без портала из кадра, а портал нарушает контракт встраивания.
- **Подложка неактивна, пока открыто окно комментария.** Клик снаружи в этом состоянии не закрывает оверлей намеренно (окно комментария модально для оверлея, пока его не отправили, не отменили или не закрыли), поэтому используйте `Отмена`, `×` или `Escape`.
- **Выделение сообщений и профилей — только указателем.** Строки диалогов отдают `aria-pressed` и работают с клавиатуры, но у строк сообщений и карточек профиля переключения с клавиатуры пока нет; используйте выделение строк диалогов или рамку области.
- **Бюджет промпта — на стороне клиента.** Оверлей держит до 50 чипов и помечает отброшенное; значение по умолчанию 12 объектов из конфигурации сегодня только публикуется через `/status` и на узле не применяется, поэтому промпт ограничен лимитами браузера (50 объектов, 500 символов на объект, 6000 всего), а не значением конфигурации.
- **Нет живых обновлений.** Список диалогов и открытая лента опрашиваются (≈15 с и ≈4 с, пока оверлей открыт и документ виден). Для push-обновлений нужен upgrade-маршрут, он не реализован.
- **Только текст.** Нет скачивания и отправки медиа, стикеров, опросов, геопозиции, звонков и секретных чатов; вложения показываются только метаданными. Нет редактирования, пересылки, закрепления и удаления сообщений.
- **Это не официальный Telegram Desktop.** Движок — `telegram@2.26.22`, который npm помечает как архивный (развитие продолжается в форке `teleproto`); версия зафиксирована намеренно, а движок изолирован в `lib/host/telegram/client.js`.
- **Мобильный drawer** (уже 768 px) находится выше оверлея; открытие drawer закрывает оверлей.
- **Реальный вход не покрыт CI.** Юнит-набор и живые дымовые проверки выполняются без аккаунта: фактический вход по QR, реальные диалоги и живой обмен по MTProto требуют ваших `api_id`/`api_hash` и вашего телефона.

## Разработка

